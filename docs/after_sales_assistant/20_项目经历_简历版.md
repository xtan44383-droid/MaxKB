**项目名称**：基于 MaxKB 的 3C 数码售后智能助手（主仓二开）  
**角色**：二开 / LLM 应用（按你实际填写）  
**时间**：（自行填写）

**项目简介**：在开源 MaxKB 主仓上，面向 3C 数码售后场景做**领域化二次开发**：落地可开关的「售后模式」、导入侧差异化分块与元数据、检索侧结构化加权、弱证据拒答与高风险承诺拦截；完成与通用模式 OFF/ON 的对照评测。同期在**不改坏存量行为**的前提下，完成管理端品牌化与对话溯源展示优化；在**数据支路**上打通 Text2SQL 演示工作流，并在平台执行层增加**演示库 SQL 入参统一门闸**（Markdown 剥离与只读白名单），使多工作流共享同一套安全规则。

**责任与亮点（二开导向）**：

- 知识库级「售后模式」开关（默认关、仅影响后续导入），导入链路按售后文档类型做分块与元数据沉淀，支撑后续检索加权与型号相关召回。
- 对话链路：检索结果结构化加权；证据不足或高风险场景走系统层拒答与后置合规拦截；流式与块式路径对齐，降低流式过程中不当承诺的暴露面。
- 评测与交付：同一应用与知识库下 OFF/ON 对照；200 题扩样本上业务可用率、高风险合规率、平均耗时等主指标优于关闭售后模式（详见仓库内 `17_对照实验报告.md` 与 `18_项目说明_面试版.md`）。
- Text2SQL：画布侧完成「意图分流 → 只读演示库查询 → 自然语言总结」链路；源码侧在 `ToolExecutor` 执行自定义工具前统一处理 `sql` 入参（`demo_sql_gate`），对 `after_sales_demo` 与工具脚本内校验规则对齐，便于多应用复用与简历表述为平台层规则。
- 产品化呈现：管理端与登录流程对外品牌收敛为「3C 数码售后助手」；移除跳转上游商业订购链；登录主题图与 Logo 展示方式调整，避免中文标识在部分环境下显示异常。

**量化结果（主口径，与 18/19 一致，面试时可择要背诵）**：

- 200 题扩样本：`business_useful_rate` 由 0.85 提升至 1.0；`high_risk_compliance_rate` 由约 0.80 提升至 1.0；`avg_latency_s` 由约 6.2s 降至约 4.5s；拒答正确率在少量样本上由 0.33 提升至 0.5（拒答子集较小，作辅证）。关键词子串通过率下降与「合规优先、不硬凑题库短语」策略一致，简历主数字建议以业务与合规指标为主。

**规划内未实施或仅讨论、可写为「可扩展」**（诚实边界，面试追问时用）：

- Neo4j 知识图谱、Text2SQL 更深改造（审计表、多库策略、与对话管道深度编排）、LLM-as-judge 全链路、与「仅影响后续导入」完全一致的 UI 删库重导切段验收等：已在项目规划文档中列为后续或 V2 方向，**未作为本轮交付写死**。
