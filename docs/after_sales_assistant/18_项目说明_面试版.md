# 18 项目说明（面试版）

## 1. 项目背景

我在 MaxKB 主仓上做了一个 3C 数码售后场景的领域化 RAG 二开。目标不是做泛客服问答，而是把通用知识检索链路改造成更适合售后规则场景的系统能力。

这个场景的核心难点有两个：
- 同样是“能不能保修/退换”，不同品牌和型号规则差异很大
- 高风险问题一旦答错，会产生承诺风险（免费维修、换新、费用、时效）

## 2. 我做的改造

### 2.1 售后模式开关（产品化入口）

- 在知识库设置页新增“售后模式”开关，默认关闭
- 状态持久化到知识库 `meta.after_sales_mode`
- 提示“切换仅对后续导入内容生效”

这样做的价值是：对存量用户无影响，领域化能力显式开启，便于灰度和回滚。

### 2.2 导入分块按售后文档类型走差异化策略

- 针对品牌型号、保修拒保、退换货、SOP、维修渠道、FAQ 等类型做识别
- 开启售后模式时做分块后处理，减少规则条款、列表项、条件句被切散
- 文档元数据增加 `after_sales_doc_type`，为后续召回加权提供依据
- 同时写入结构化字段骨架：`after_sales_brands`、`after_sales_model_tokens`（从文件名与首段内容抽取），用于在线检索加权

这样做的价值是：离线分块更贴近售后规则结构，减少“召回到半条规则”。

### 2.3 检索链路增加结构化信息加权

- 在原召回基础上增加售后模式重排
- 识别问句中的型号、SN/IMEI 等结构化 token
- 命中结构化字段的段落加分；问句有明确型号时优先保留对应证据

这样做的价值是：降低错型号、错规则召回。

### 2.4 弱证据拒答与高风险合规

- 在系统层新增拒答判定，不只依赖 prompt
- 证据不足、高风险且证据弱、型号不匹配等场景直接走固定模板拒答
- 禁止在证据不足时直接承诺保修/换新/免费维修/费用/时效
- 增加高风险承诺词后置拦截，避免模型输出中出现“一定保修/免费维修”等越权承诺
- 流式与块式对齐：售后上下文的模型生成流，正文先缓冲并在结束后执行同一套后置拦截，再一次性输出，降低流式过程中“先泄露高风险措辞”的概率

这样做的价值是：把“回答好听”转为“业务风险可控”。

## 3. 实验与结果

### 3.1 baseline 读取结论

- baseline 首轮共 292 题，规则通过率 0.0%
- 主因是请求或 HTTP 异常，不是单纯模型能力问题
- 应用 ID 为 `019dd098-7fbd-7f61-a017-f5a541697702`

### 3.2 本轮推进结果

- V1 核心改造代码已落地（后端+前端）
- 已完成 20 题稳定性烟测，连接拒绝类问题未复现
- 已完成 120 题与 200 题扩样本 OFF/ON 对照，并形成业务主指标汇总（见 `17_对照实验报告.md` 第 9～10 节）
- 200 题扩样本（同应用、同知识库、同题集切片）关键结论（主验收口径）：
  - `business_useful_rate`：`0.85 -> 1.0`
  - `high_risk_compliance_rate`：`0.8049 -> 1.0`
  - `refusal_correct_rate`：`0.3333 -> 0.5`（拒答样本数为 6）
  - `avg_latency_s`：`6.2148 -> 4.4552`
- 关键词子串通过率（辅指标）在 200 题上为 `5.5% -> 3.5%`，更符合“合规优先时不硬凑题库短语”的现象，不建议单独作为简历主数字

### 3.3 仍未纳入本轮交付的项（边界说明）

- LLM-as-judge：需要单独 judge 模型与密钥配置，本轮未接入自动打分链路
- 与规划文档完全一致的离线切段验收：需要 UI 侧删除旧文档并按售后模式重新导入，本轮对照以在线策略与元数据增强为主

## 4. 我在项目里的价值

- 能把业务风险点翻译成平台能力（开关、分块、检索、拒答、合规）
- 能在主仓做最小范围二开，不破坏原有功能
- 能用对照实验思路推进，不把 baseline 与改造结果混在一起

## 5. 面试常见追问（简答口径）

1) 为什么要做拒答，不怕体验差吗？  
高风险售后场景里，错误承诺的代价远高于一次澄清，拒答是为了降低业务风险。

2) 为什么不是先扩更多数据？  
先控制变量验证平台改造有效，再扩样本，才能证明“改造价值”而不是“数据堆量”。

3) 你这次二开和调 prompt 的区别是什么？  
我做的是系统层能力：导入分块、检索加权、拒答拦截、配置开关，稳定性和可控性更高。

4) 怎么保证不影响老用户？  
售后模式默认关闭，关闭时保持原行为，且开关仅影响后续导入内容。
