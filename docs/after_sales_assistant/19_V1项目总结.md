## 5. 200 题扩样本结论（主验收口径）

详见 `17_对照实验报告.md` 第 10 节，这里只保留结论摘要：

- `business_useful_rate`：`0.85 -> 1.0`
- `high_risk_compliance_rate`：`0.8049 -> 1.0`
- `refusal_correct_rate`：`0.3333 -> 0.5`（拒答样本数为 6）
- `avg_latency_s`：`6.2148 -> 4.4552`
- 关键词子串通过率（辅指标）：`5.5% -> 3.5%`

解读：当系统更偏合规与拒答时，固定短语命中会下降，但业务可用性与高风险合规会上升；因此主 KPI 应以业务指标与合规指标为主。

## 6. 本轮明确不纳入交付的边界

- LLM-as-judge：需要独立 judge 模型与密钥，避免与回答模型同源；本轮未接入自动调用链。
- 与「开关仅影响后续导入」完全一致的切段验收：需要 UI 删除旧文档并按售后模式重新上传同一批知识库后再对照。

## 6.1 流式输出与后置拦截的一致性说明

售后场景的后置拦截需要完整答案文本判断。为避免流式过程中先推送正文、后置拦截无法撤回的风险，在售后上下文且为模型生成流时，正文采用「先缓冲、生成结束后一次性输出」的策略；若仍触发后置拦截，则输出固定拒答模板，并与块式路径使用同一套判定函数。

## 7. 复现命令（默认在本机服务已启动的前提下）

评测与对照的具体输入文件路径以你机器上的题集切片为准；对照脚本的典型用法为：

```bash
cd /home/tlx/projects/MaxKB
```
