# 3C 数码售后助手：知识库目录设计

## 1. 目标

本目录用于准备一套适合 MaxKB 导入的 3C 数码售后知识库原始文档，服务于后续领域化 RAG 二开：

- 3C 售后知识问答
- 型号级规则匹配
- 故障诊断与处理 SOP
- 保修 / 退换 / 维修政策查询
- 高风险问题的拒答与澄清

## 2. 推荐目录结构

```text
mock_data/
  knowledge/
    3c_after_sales/
      model_apple_iphone15_基础信息与保修规则.md
      model_huawei_matebook14_常见故障与处理.md
      policy_general_保修与拒保判定.md
      policy_platform_电商平台退换货说明.md
      sop_phone_不开机排障流程.md
      sop_camera_镜头报错排查流程.md
      faq_common_高频售后问答.md
```

知识库主格式建议统一用 `Markdown`。`TXT` 仅适合临时整理，`PDF` 只建议作为原始素材来源，不建议直接作为最终导入格式。

## 3. 文档分类建议

### 3.1 品牌 / 型号资料

适合存放：

- 品牌与品类说明
- 型号差异说明
- 版本 / 容量 / 套装差异
- 常见故障现象与适配配件

建议字段标签：

- 品牌
- 产品型号
- 产品类别
- SKU / 版本
- SN / IMEI
- 文档类型

### 3.2 售后政策

适合存放：

- 保修期说明
- 拒保条件
- 退换货说明
- 维修 / 检测 /寄修规则

建议字段标签：

- 政策类型
- 生效时间
- 适用品类
- 责任判定

### 3.3 服务流程 / SOP

适合存放：

- 客服首问处理流程
- 远程排障标准话术
- 型号信息补齐流程
- 升级到人工 / 维修点的条件
- 工单关闭前核验清单

建议字段标签：

- 流程阶段
- 角色
- 优先级
- 适用品类

### 3.4 FAQ / 高风险问答

适合存放：

- 用户高频追问
- 保修争议类问题
- 维修费用 / 时效类问题
- 证据不足时的固定澄清口径

建议字段标签：

- 风险等级
- 问答类型
- 是否允许直接回答
- 需补充字段

## 4. 第一版建议知识范围

为了保证第一版开发收敛，建议优先覆盖以下范围：

1. 手机、电脑、相机等 3C 品类的通用字段骨架
2. 2 到 3 个品牌的核心型号规则
3. 1 套保修 / 拒保政策文档
4. 1 套退换 / 维修规则文档
5. 1 到 2 套排障 SOP
6. 1 套高频 FAQ / 高风险话术文档

## 5. 第一版重点问答类型

### 5.1 知识问答

- iPhone 15 的标准保修期是多久？
- 某型号笔记本进液后是否还能保修？
- 相机镜头报错应该先做哪些排查？
- 用户没有发票时还能申请保修吗？

### 5.2 知识 + 工单混合问答

- 某型号黑屏的处理步骤是什么？最近 7 天这类工单多不多？
- 哪些型号常见故障最多？对应保修规则是什么？
- 哪些工单需要优先升级人工？判定条件是什么？

## 6. 对 MaxKB 二开的用途

这批知识文档后续可以直接用于：

1. 导入知识库，验证基础 RAG 能力
2. 验证 3C 场景的差异化分块与检索
3. 支撑型号级规则匹配与高风险拒答
4. 配合工单数据做问题路由与升级判断

## 7. 当前已生成的模拟文档

当前建议在 `mock_data/knowledge/3c_after_sales/` 下逐步整理以下类型文档：

- `model_*`：品牌 / 型号资料与型号专属规则
- `policy_*`：保修、拒保、退换、维修政策
- `sop_*`：排障流程、升级流程、客服标准口径
- `faq_*`：高频问答与高风险问题澄清模板
