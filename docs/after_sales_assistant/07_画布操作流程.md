# 画布操作流程：售后助手工作流（知识库 + Text2SQL）

> 同目录文档已按推荐阅读顺序编号：`00`～`08`，索引导航见 [00_文档阅读顺序.md](./00_文档阅读顺序.md)，本文为 `07`。

本文说明如何在 MaxKB **高级智能体**的画布上，搭建当前项目需要的工作流，以及**每个常用节点里建议填什么**。界面文案以中文产品为准；若你使用的版本菜单名称略有差异，以「同含义」为准。

## 一、开始前请确认

1. **自定义工具**已创建，且调试运行成功（见上文 Text2SQL 文档第一节）。
2. 本机 **Web** 与 **Celery** 按 [01_本地运行与启动.md](./01_本地运行与启动.md) 已启动（涉及向量化等后台任务时必需）。
3. 演示库 **after_sales_demo** 已导入（`mock_data/sql/schema.sql`、`seed.sql`）。

---

## 二、创建应用入口

1. 在应用列表点击 **创建** → 选择 **高级智能体**（低代码拖拽画布）。
2. 填写名称、描述后选择模板：
   - **只想先跑通「查数」一条链**：选 **空白创建**。
   - **希望自带知识库检索骨架、再改成分流**：可选 **知识库问答助手**，再在画布上增加意图与数据支路（改动量略大）。
3. 创建后进入 **工作流 / 画布** 编辑页。

---

## 三、方案 A：仅 Text2SQL（最小可运行链）

适合：**先验证「AI → 工具 → 再 AI」**能跑通，暂不接知识库与意图。

### 3.1 节点顺序（从左到右）

```
开始 → AI 对话（生成 SQL）→ 工具（自定义安全查询）→ AI 对话（结果转自然语言）→ 结束
```

在画布上：从右侧 **基础组件** 拖 **开始**（通常已有）、两个 **AI 对话**；从 **工具** 页签拖你的 **自定义工具** 节点（名称以你创建的工具为准）。用连线或节点间的 **+** 按上述顺序接好。

### 3.2「开始」节点

| 项目 | 说明 |
|------|------|
| 作用 | 接收用户当前输入，输出里一般有 **用户问题**（界面可能显示为 `question` 等）。 |
| 你需要做的 | 一般使用默认即可；后续占位符多为 `{{开始.question}}` 形式（若你的版本显示为节点 ID，在变量选择器里选「开始节点的 question」即可）。 |

### 3.3 第一个「AI 对话」节点（只负责生成 SQL）

| 区域 | 建议填写 |
|------|----------|
| **AI 模型** | 选择你已配置好的模型。 |
| **系统提示词** | 打开 [04_Text2SQL_工具与工作流说明.md](./04_Text2SQL_工具与工作流说明.md) 第三节 **「AI 节点用表结构摘要」**，将代码框内**整段**复制粘贴到系统提示词中。 |
| **用户提示词** | 只喂用户问题，**不要**引用知识库检索结果（本链路与 RAG 无关）。示例：`用户问题如下，请只输出一条 SQL：\n{{开始.question}}`（占位符以画布变量选择器为准）。 |
| **历史聊天记录** | 按需开启；若多轮 SQL 易混乱，可先减少条数或关闭做对比。 |
| **技能 / 工具（本节点内）** | 若画布上**已有独立的「工具」节点**承接 SQL，则**不必**在本 AI 内再绑定同一个查库工具，避免重复执行逻辑混乱。 |
| **输出** | 下游工具需要 **纯 SQL 文本**；一般映射 **本节点 AI 文本输出**（界面常标为 `answer` 或「AI 回答内容」）到工具的入参 `sql`。 |

### 3.4「工具」节点（自定义工具 / 工具库）

| 项目 | 说明 |
|------|------|
| **选择工具** | 选择你已创建的「售后演示库只读查询」类自定义工具。 |
| **启动参数** | 若在应用层要求再次填写，与创建工具时的默认值一致：`host`、`port`、`user`、`password`、`database`（演示库 `after_sales_demo`）。 |
| **输入参数 `sql`** | 映射为 **上一个 AI 对话节点的文本输出**（在映射界面点选「上一节点」的 answer / 回答内容）。勿手写死 SQL（除非仅做连通性测试）。 |

保存后建议用调试或对话测一句：`SELECT COUNT(*) FROM tickets LIMIT 10` 类问题，看工具是否被调用、返回 JSON 是否正常。

### 3.5 第二个「AI 对话」节点（把查询结果说成人话）

| 区域 | 建议填写 |
|------|----------|
| **系统提示词** | 说明角色与约束，例如：你是售后数据分析助手；**必须严格根据下方「查询结果」中的数字与字段回答**，禁止编造；若结果为错误或 `ok` 为 false，用简短中文说明原因并建议用户换种问法。 |
| **用户提示词** | 同时提供「原始问题」与「工具 JSON」，便于对照总结。示例结构：`用户问题：\n{{开始.question}}\n\n查询结果（JSON）：\n{{工具节点.xxx}}` —— **第二处占位符**：请点击变量插入，选择**工具节点**对应的**执行结果 / result / data**（以你界面实际字段名为准）。 |
| **技能 / 工具** | 通常**不需要**再挂查库工具；本步只做自然语言总结。 |

### 3.6「结束」节点

将 **第二个 AI 对话** 的输出接到结束（或按你版本要求选择「回复用户」的最终变量），保证对话窗口展示的是**总结后的中文**，而不是原始 JSON。

## 四、方案 B：单边意图分流（同一入口：知识 或 数据）

与 [06_单边意图分流_工作流配置.md](./06_单边意图分流_工作流配置.md) 一致：**每次只走一条路**。

### 4.1 节点顺序（概念）

```
开始 → 意图识别 → ┬→ 查知识分支：知识库检索 → AI 对话 → 结束
                    └→ 查数据分支：（同方案 A）AI → 工具 → AI → 结束
```

在画布上为「意图识别」的**每个意图出口**各拉一条线，分别接上知识链与数据链；**不要**把「知识库检索」的输出接到「生成 SQL」的 AI 上。

### 4.2「意图识别」节点

| 项目 | 建议 |
|------|------|
| **意图** | 至少两类：**查知识**、**查数据**；名称可自定，建议语义清晰。 |
| **例句** | 每类各写几条典型说法（文档第四节表格可参考）。 |
| **未匹配 / 其他** | 建议默认走 **查知识**，降低误触数据库概率（与单边分流文档一致）。 |

### 4.3「查知识」分支

| 节点 | 建议 |
|------|------|
| **知识库检索** | 选择已导入的售后知识库；问题变量选 `{{开始.question}}`（或等价项）。 |
| **AI 对话** | 系统提示词：根据检索片段回答政策、步骤、故障说明等；**用户提示词**中引用 `{{知识库检索.data}}`（或你界面上的检索结果字段）与 `{{开始.question}}`；不要求输出 SQL。 |

### 4.4「查数据」分支

与 **第三节方案 A** 完全一致：**第一个 AI（仅 SQL + 表结构在系统提示词）→ 工具（sql 映射）→ 第二个 AI（JSON 转人话）**。  
注意：**本分支第一个 AI 的用户提示词里不要出现 `{{知识库检索.data}}`**。

### 4.5 两条分支汇合

按你使用的应用类型：两条线分别接到各自的 **结束** 或统一结束节点，确保用户只看到**当前支路**生成的主回复。

---

## 五、占位符 `{{节点.字段}}` 怎么填对

1. 在 **用户提示词 / 系统提示词** 输入框旁，一般有 **插入变量** 或 `{x}` 选择器；**优先用选择器插入**，避免手打拼错节点名。
2. 不同版本节点显示名可能是 **中文名** 或 **节点 ID**；只要来源是「开始 → question」「知识库检索 → data」「工具 → 执行结果」即可。
3. 改完画布后务必 **保存并发布**（若有发布按钮），否则对话入口可能仍用旧版本。

## 七、常见问题

| 现象 | 可能原因与处理 |
|------|----------------|
| 工具收不到 SQL | 检查工具入参 `sql` 是否映射到 **第一个 AI 的输出**，不是第二个 AI。 |
| 模型输出带 Markdown 或解释文字 | 加强系统提示词「只输出 SQL 文本」；或在工作流中增加「只取代码块」类节点（若版本支持）。 |
| 连接库失败 | 检查工具启动参数密码是否为**纯密码字符串**（不要带「演示库密码：」等说明文字）；确认 Postgres 与库名 `after_sales_demo`。 |
| 启动参数添加后只剩一行 | 每次用 **+ 添加** 新增一行；若曾打开某行编辑后点取消，可关闭抽屉重新进入再添加（见历史交接说明）。 |
