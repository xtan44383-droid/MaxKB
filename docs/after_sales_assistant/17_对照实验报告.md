已读取 baseline 报告，确认以下事实成立：
- baseline 首轮结果已落盘

## 4. 本轮改造内容（V1 已落代码）

### 4.1 后端：售后模式分块

文件：`apps/knowledge/serializers/document.py`

已实现：
- 从知识库 `meta.after_sales_mode` 读取开关
- 售后模式开启时，对导入文档做类型识别（品牌型号、保修拒保、退换货、SOP、维修渠道、FAQ/高风险）
- 对脆弱分段做合并，降低列表项/条件句被切散概率
- 在文档元数据写入：
  - `after_sales_mode: true`
  - `after_sales_doc_type: <类型>`

### 4.2 后端：召回加权与型号优先

文件：`apps/application/chat_pipeline/step/search_dataset_step/impl/base_search_dataset_step.py`

已实现：
- 在原召回逻辑后增加售后模式重排
- 提取型号/SN/IMEI 等结构化 token
- 对命中型号/SN/IMEI 的段落加分
- 问句有明确型号时，优先保留命中型号的召回结果

### 4.3 后端：弱证据拒答与高风险约束

文件：`apps/application/chat_pipeline/step/chat_step/impl/base_chat_step.py`

已实现：
- 售后模式上下文下增加系统级拒答判断
- 触发条件包括：
  - 无证据或证据过弱
  - 高风险问句且证据不足
  - 问句含型号但证据中无对应型号
- 使用固定拒答模板（按需求文案）
- 流式输出路径对齐：售后上下文且为模型生成流时，正文先缓冲并在生成结束后执行与块式路径一致的后置拦截，再一次性输出正文，降低“先输出高风险措辞、后无法撤回”的风险

### 4.4 前端：知识库设置页开关

文件：`ui/src/views/knowledge/KnowledgeSetting.vue`

已实现：
- 新增“售后模式”开关（默认 false）
- 保存到知识库 `meta.after_sales_mode`
- 页面提示“切换仅对后续导入内容生效”

## 9. 第二轮业务口径对照（120题）

本轮对系统级拒答与高风险约束做了收敛，目标是提升业务可用性，而不是单纯追关键词命中。

- 对照文件：
  - OFF：`/tmp/after_sales_off_120.json`
  - ON（第二轮）：`/tmp/after_sales_on_120_v2.json`
  - 汇总：`/tmp/after_sales_compare_120_v2.json`

### 9.1 业务指标变化（OFF -> ON v2）

- keyword_pass_rate：`0.0583 -> 0.0333`（下降）
- avg_latency_s：`7.2961 -> 4.3963`（降低 `2.8998s`）
- refusal_correct_rate：`0.0000 -> 0.5000`（提升）
- high_risk_compliance_rate：`0.8036 -> 1.0000`（提升）
- business_useful_rate：`0.8750 -> 1.0000`（提升）

### 9.2 解读

这一轮出现了典型的“规则命中率下降、业务价值上升”：
- 关键词通过率下降，说明答案不再强行贴题库中的固定措辞
- 拒答正确率与高风险合规率明显提升，说明系统在高风险场景更保守、更可控
- 平均时延下降，说明大量高风险问题在前置规则层被更快拦截

因此，当前更适合把“关键词通过率”作为辅指标，把“拒答正确率、高风险合规率、业务可参考率”作为主验收指标。
